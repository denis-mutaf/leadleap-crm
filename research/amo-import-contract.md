# Amo → CRM: контракт переноса и переключения

Снимок API от 20.09.2026: SHA-256 манифеста
`eead5bc5d7cb366a94950fcf0067ad49dde5a88497db267cda0bb85935838203`.
Закрытая таблица `amo_import_records` содержит 67 588 уникальных записей;
авторизованный пользователь не видит ни одной. Это источник для повторяемого импорта,
а не экранная таблица CRM.

## Этапы

Новые 12 этапов создаются отдельно от восьми демоэтапов. Четыре статуса
резервации Amo ведут в один этап CRM; связь хранится в `amo_stage_map`.

Резервация Select, Next, нового объекта и D. Tudor добавляет соответствующий

на старте выключены: в Amo эти поля массово пусты, а форма их заполнения в CRM

0 сделок. Во второй воронке Sprevanzare тоже 0 сделок; её этапы не подменяют
основную карту.

## Сохранение исключений

- 8 сделок без контакта получают отдельный синтетический контакт; исходный lead
  остаётся в закрытом снимке. Для 13 сделок с двумя контактами первый становится
  основным, обе связи сохраняются в `deal_contacts`. Всего после этого должно
  быть 5 762 связи сделки с контактом.
- 48 проигранных сделок без причины получают справочное значение
  «Не указана в Amo». Причина из Amo сохраняется без замены там, где она есть.
- 406 повторных телефонов не объединяют людей автоматически. Все 4 694 исходных
  значения сохраняются в `imported_contact_phones`; `contact_phones` получает
  единственного канонического владельца нормализованного номера. Шесть значений,
  которые не нормализуются, остаются с `normalized_phone = null`.
- 52 уникальных тега берутся из обоих справочников Amo: сделок и контактов.
  Общий ID связывается с одной строкой CRM. Сохраняются 13 341 связь сделки с
  тегом и 644 связи контакта с тегом.
- Ответственный Amo `0` становится `owner_id = null` с сохранением исходного ID
  в снимке. Пять настоящих пользователей Amo получают отдельные учётные записи;
  импорт не рассылает приглашений или писем.
- Пустой текст задачи получает читаемое название по типу задачи; исходный объект
  и результат остаются в снимке/`amo_result`. Одна задача не имеет ни
  `entity_type`, ни `entity_id`. Она остаётся в CRM как явно неразобранная,
  без выдуманной связи.
  У завершённых задач Amo нет отдельного времени закрытия: `done_at` берётся из
  `updated_at` и считается приближённым.
- 14 125 примечаний переносятся как текстовые записи или записи звонка с
  `amo_note_type`/`amo_params`. Из 7 502 записей о звонках создаются строки
  `calls` с исходными параметрами; числовые статусы Amo не подменяют статусы
  Moldcell PBX. 39 950 уникальных событий уже сохранены в снимке; из 2 348
  событий смены этапа 2 323 относятся к экспортированным сделкам, а 25 — к
  отсутствующим. Историю доступных переходов импортировать с исходным временем
  отдельно, без создания ложных действий менеджеров на дату переезда.
- `deals.amount` хранит цену сделки, `deals.budget` — бюджет квалификации.
  Свободный срок покупки и пять значений резидентства не сжимаются до текущих enum.
  Исходный ID источника и точный status ID сохраняются отдельно. Свободный текст
  первого взноса, ежемесячной платы, комнат и все Amo custom fields остаются
  доступными в карточке через отдельные поля; неоднозначные диапазоны и проценты
  не переводятся в фиктивные числовые суммы.

## Порядок и проверка

1. Зафиксировать резервную копию конкретных 35 демосделок и связанных записей
   в игнорируемой `.scratch/amo-cutover/`, с хешем и явным списком UUID.
2. Подготовить справочники, пять профилей и карту этапов идемпотентно.
3. Импортировать контакты, связи и телефоны; затем сделки, проекты, теги,
   задачи, примечания и исторические переходы. Ни одна фаза не удаляет демо.
4. Сверить ровно 5 924 контакта, 5 749 сделок, 1 707 задач, 14 125 заметок,
   распределение стадий и сумму 185 ненулевых цен (€ 7 915 168).
   Проверить отсутствие неизвестных FK и ошибки RLS на менеджере.
5. Одной транзакцией включить новые этапы, убрать старые демоэтапы и удалить
   только UUID из резервного манифеста. После переключения пройти браузерный QA.

Если любой счётчик или связь не сходится, переключение не выполняется.
